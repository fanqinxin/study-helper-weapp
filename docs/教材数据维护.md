# 教材数据维护

「课文同步练习」的内容全部来自数据库，不在代码里。这份文档说明数据长什么样、怎么灌、怎么加新教材。

数据文件：`server/data/textbook/*.json`
灌库脚本：`server/scripts/seed.js`

---

## 一、为什么教材数据单独维护

`sql/schema.sql` 只放表结构，教材内容放在 JSON 里。两个原因：

1. **教材是会变的**。修订版换课文、换单元顺序，改 JSON 就行，不用碰表结构，也不会因为重跑迁移把内容冲掉。
2. **内容需要校对**。JSON 可以整份发给老师或教研看，改完再灌。

---

## 二、现在有什么

`bnu-chinese-g1-v1.json` —— 北师大版 · 语文 · 一年级上册

- 32 篇课文，覆盖 16 个单元（从「上学了」到「第十六单元 成长」）
- 每课 3 道**单选题**，共 96 题
- 全单选是刻意的：一年级孩子打字慢，点选选项才能真的做完；填空和阅读理解等中高年级再加

> `语文天地`、`认字表`、`写字表` 这些复习页没有作为课文录入，所以 `seq` 是**正文课文的序号**，不完全等于课本页码顺序。如果你希望「同步课堂」严格跟随课本页序，把复习页也加成课文即可（标题写「语文天地一」）。

## 三、数据结构

```json
{
  "name": "北师大版",          // 教材版本名，会显示在教材选择页
  "subject": 1,                // 1=语文 2=数学 3=英语
  "grade": 1,                  // 1-6
  "volume": 1,                 // 1=上册 2=下册
  "publisher": "北京师范大学出版社",
  "note": "给维护者看的备注，不入库",
  "lessons": [
    {
      "seq": 1,                // 第几课，正整数，同册内唯一
      "title": "上学了",
      "unit": "上学了",        // 单元名，前端按它分组显示
      "knowledgePoints": ["入学适应", "识字启蒙"],
      "questions": [
        {
          "type": 1,           // 1=单选 2=填空 3=阅读理解 4=计算
          "stem": "放学离开学校时，应该对老师说什么？",
          "options": ["老师再见", "老师早", "谢谢", "对不起"],
          "answer": "老师再见",  // 必须是 options 里的原文
          "analysis": "离开时说“再见”，是基本的礼貌用语。",
          "difficulty": 1      // 1-3
        }
      ]
    }
  ]
}
```

### 三个容易踩的坑

| 坑 | 后果 | 脚本会拦吗 |
|---|---|---|
| `answer` 写成选项的**字母**（如 `"A"`） | 判分永远错 | ✅ 校验时报「answer 不在选项中」 |
| `seq` 重复 | 两篇课文互相覆盖 | ✅ 校验时报重复 |
| 同一课里**题干重复** | 幂等更新会命中错题 | ✅ 校验时报题干重复 |

判分逻辑在 `services/textbook.js` 的 `submitLesson`：拿用户提交的字符串和 `answer` 做**去空格、忽略大小写**的精确比对。所以选项和答案必须写成同一串字，包括标点。

## 四、怎么灌

### 服务器（Docker）

```bash
# 首次
docker compose --profile tools run --rm seed

# 改完 JSON 后重跑（幂等，不会重复）
docker compose --profile tools run --rm seed

# 只想灌某一册
docker compose --profile tools run --rm seed bnu-chinese-g1-v1

# 重建这套教材（先删该教材下所有课文和题目，再建）
docker compose --profile tools run --rm seed --reset

# 只校验数据，不写库
docker compose --profile tools run --rm seed --dry-run
```

> 改完 JSON 需要重新构建镜像，因为 JSON 是打进镜像里的：
> `docker compose build api && docker compose --profile tools run --rm seed`
> 或者直接进容器灌：`docker compose cp server/data/textbook/. api:/app/data/textbook/` 再执行 `docker compose exec api node scripts/seed.js`

### 本地

```bash
cd server
npm run seed:check     # 先校验
npm run seed
```

**建议顺序**：先 `--dry-run` 看校验结果，全过了再真灌。脚本是「全部文件校验通过才写库」，一个文件有问题整批都不写。

## 五、幂等规则

| 对象 | 匹配键 | 重复执行时 |
|---|---|---|
| 教材 | `name + subject + grade + volume`（且 `is_custom=0`） | 复用，不改 id |
| 课文 | `textbook_id + seq` | 更新标题 / 单元 / 知识点 |
| 题目 | `lesson_id + stem` | 更新题型 / 选项 / 答案 / 解析 |

这套键的好处：**教材 id 不变**，用户表里存的 `textbook_id` 不会失效；**课文 id 也不变**，用户 `lesson_progress` 不会错乱。

`--reset` 是例外：它会删掉课文重建，`lesson.id` 全变。用户表只存 `lesson_progress`（整数序号）和 `textbook_id`，所以进度不会丢，但如果将来有「某课收藏」这类按 `lesson_id` 记的数据，`--reset` 前要评估。

## 六、加一套新教材

1. 复制 `bnu-chinese-g1-v1.json`，改文件名（建议 `{版本拼音}-{学科}-{年级}-{上下册}.json`，如 `bnu-math-g1-v1.json`）
2. 改顶部的 `name` / `subject` / `grade` / `volume`
3. `npm run seed:check` 校验
4. `npm run seed` 灌库

不用改任何代码：

- 教材选择页调 `/textbook/list?subject=&grade=&volume=`，新教材自动出现
- 课文列表读 `lesson.unit` 分组，单元名怎么写就怎么显示

## 七、内容质量提醒

种子数据是我按北师大版目录和课标知识点生成的，**上线前建议让老师过一遍**，重点看三类：

1. **课文标题与现行修订版是否一致**（教材换版时篇目会变）
2. **答案是否有歧义**（一年级题目最容易出「好像两个都对」）
3. **题干用词是否超纲**（一年级上册还没学的字，尽量不出现在题干里）

改法只有一步：改 JSON 里对应字段，重跑 `seed`。
